# linux.sb 自动回帖机器人

在烧饼社区(linux.sb)上,每 60 秒检测一次新帖,自动生成并发布一条中文回帖。

- 零第三方依赖,只用 Python 标准库
- 自动登录、自动续期,不用手动维护 Cookie
- 默认 **只生成不提交**(dry-run),确认质量后再开启真实发布

---

## 一、快速开始

1. 双击 `启动机器人.bat`(首次会自动复制出 `config.json`)
2. 用记事本打开 `config.json`,至少填四项:
   - `username` / `password` —— bot 账号(不是你的主账号)
   - `llm.base_url` / `llm.api_key` / `llm.model` —— AI 接口
3. 再次双击 `启动机器人.bat`
4. 观察日志里生成的回复内容,满意后把 `dry_run` 改成 `false`
5. 按 `Ctrl+C` 停止

## 二、运行前必须确认

- **代理必须开着**。linux.sb 直连超时,`config.json` 的 `proxy` 要指向你 Clash 的
  HTTP 端口(默认 `http://127.0.0.1:7897`)。代理没开时机器人会登录失败并退出。
- **用 bot 专用账号**。不要复用主账号,主账号的登录凭证泄露风险太高。

## 三、配置说明

| 字段 | 说明 |
|---|---|
| `poll_interval` | 轮询间隔,秒。默认 60 |
| `daily_limit` | 每日最多回复条数,默认 20。防止刷屏 |
| `reply_delay_min/max` | 检测到新帖后随机等待的秒数,降低机器味 |
| `deny_forums` | 不回复的板块。默认 `[2, 8]`(福利放送、我要推广) |
| `allow_forums` | 若填写,则只回复这些板块(优先于 deny) |
| `deny_keywords` | 标题命中即跳过,用于滤掉发卡 / 赠送 / 兑换类推广帖 |
| `system_prompt` | 留空则使用内置提示词 |
| `context_scope` | `op` = 用楼主全部发言做上下文(默认);`first` = 只用首楼 |
| `enable_search` | 是否联网搜索,给 AI 补充帖子之外的背景 |
| `search_sources` | 搜索来源:`google_news` / `bing` / `hn` / `github` |
| `llm.providers` | 多个 AI 接口,按顺序尝试,限速或报错自动切换 |
| `skip_gacha` | 是否跳过站点标记的发卡贴,默认 `true` |
| `dry_run` | `true` = 只生成不提交 |

板块编号:1 错误地方 / 2 福利放送 / 3 资源分享 / 4 技术交流 / 5 求助问答 /
6 社区治理 / 8 我要推广 / 9 社区公告 / 10 大禹治水

## 四、命令行参数

```
python bot.py              正常循环运行
python bot.py --once       只跑一轮就退出(调试用)
python bot.py --dry        强制只读,不提交
python bot.py --login-only 只验证登录能不能成功
```

## 五、工作原理

1. **登录** —— 账号密码登录,自动求解 Cap 人机验证(见 `cap_solver.py`)。
2. **发现新帖** —— 拉 `sitemap.xml`,与本地 `state.db` 比对,找出没见过的帖子 ID。
3. **过滤** —— 板块黑名单、站点自带的发卡贴标记、标题关键词、已回过、已锁帖,全部跳过。
4. **抓内容** —— 解析标题、板块、楼主,以及 **楼主在本帖的全部发言**(不只首楼)。
5. **联网搜索** —— 先用 AI 提炼 1~2 个关键词,再多源并行搜索,结果作为背景资料喂给模型。
6. **生成回复** —— 调 OpenAI 兼容接口;多个接口可配成 `providers` 互为备份,前一个失败自动切换。
7. **过反自动化闸门** —— 发帖前实时从帖子页解析 `_csrf`、验证码挑战与 PoW 参数:
   - `_csrf`:页面级随机值,每次请求都不同
   - PoW(标准 SHA-256 前缀匹配)/ 算术题 / 蜜罐字段 `native_captcha_company` 留空
8. **提交** —— `POST /reply_edit`,`X-Requested-With: XMLHttpRequest`,解析 JSON 结果。

## 七、注意事项

- 首次运行会把**所有存量帖子**标记为已见,不会去回复历史帖,避免一上线就爆量。
- PoW 难度低(2~5 个前导零),求解通常在 1 秒内完成。
- 若某帖发不出去,日志会记录服务端返回的原始提示,据此排查。
- 建议先跑几天 `dry_run` 观察生成质量,再考虑开放真实发布。
